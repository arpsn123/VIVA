TOPIC: Retrieval-Augmented Generation (RAG)

OVERVIEW

RAG stands for Retrieval-Augmented Generation.

It is an AI architecture that combines:

1. Information Retrieval
2. Large Language Models (LLMs)

The purpose of RAG is to allow an LLM to access external knowledge before generating an answer.

Instead of relying only on knowledge learned during training, a RAG system retrieves relevant information from documents and provides it to the LLM as context.

This significantly improves factual accuracy and enables the use of private or up-to-date information.

---

WHY RAG IS NEEDED

Large Language Models have limitations.

Problems:

1. Hallucinations

The model may generate incorrect information confidently.

2. Knowledge Cutoff

The model only knows information available during training.

3. No Access to Private Data

A company may have internal documents not included in model training.

4. Expensive Fine-Tuning

Retraining or fine-tuning models whenever data changes is costly.

RAG solves these problems by retrieving relevant information at runtime.

---

TRADITIONAL LLM WORKFLOW

User Question

↓

LLM

↓

Generated Answer

Problem:

Answer depends entirely on model memory.

If the information was not present during training, the answer may be wrong.

---

RAG WORKFLOW

User Question

↓

Convert Question to Embedding

↓

Search Vector Database

↓

Retrieve Relevant Documents

↓

Provide Documents as Context

↓

LLM Generates Answer

↓

Final Response

The LLM now answers using retrieved knowledge rather than relying solely on memory.

---

CORE IDEA OF RAG

Instead of asking:

"Answer using only what you know."

We ask:

"First retrieve relevant information, then answer using that information."

This simple change dramatically improves answer quality.

---

KEY COMPONENTS OF A RAG SYSTEM

1. Data Source

Knowledge repository containing:

* PDFs
* Text files
* Websites
* Documentation
* Databases
* Internal company documents

2. Chunking

Splitting documents into smaller sections.

3. Embedding Model

Converts text into vectors.

4. Vector Database

Stores embeddings.

5. Retriever

Finds relevant chunks.

6. LLM

Generates the final response.

---

DOCUMENT INGESTION PIPELINE

Before retrieval can happen, documents must be processed.

Pipeline:

Documents

↓

Text Extraction

↓

Chunking

↓

Embedding Generation

↓

Store in Vector Database

This is called indexing or ingestion.

Employee Handbook.pdf

STEP 2: TEXT EXTRACTION

Text must be extracted from files.

Examples:

PDF → Text

DOCX → Text

HTML → Text

OCR may be used for scanned documents.

Popular Tools:

* PyPDF
* PDFPlumber
* Unstructured
* Tesseract OCR

---

STEP 3: CHUNKING

Large documents are divided into smaller pieces.

Example:

100-page document

↓

Chunk 1

Chunk 2

Chunk 3

Chunk 4

Each chunk becomes independently searchable.

---

WHY CHUNKING IS IMPORTANT

Without chunking:

Entire document becomes one embedding.

Problems:

* Poor retrieval
* Large context size
* Reduced relevance

With chunking:

Specific sections can be retrieved.

Benefits:

* Better precision
* Better retrieval quality
* Lower token usage

---

CHUNKING STRATEGIES

Fixed Size Chunking

Example:

500 tokens per chunk.

Advantages:

* Simple

Disadvantages:

* May break sentences.

---

Recursive Chunking

Splits using:

Paragraphs

↓

Sentences

↓

Words

Advantages:

* Preserves meaning

Widely used in production systems.

---

Semantic Chunking

Chunks are created based on meaning.

Advantages:

* High retrieval quality

Disadvantages:

* More computationally expensive

---

STEP 4: EMBEDDING GENERATION

Each chunk is converted into a vector.

Example:

Chunk:

"Neural networks are inspired by biological neurons."

Embedding:

[0.23, -0.54, 0.87, ...]

The vector captures semantic meaning.

---

EMBEDDING MODELS

Popular Models:

OpenAI Embeddings

Sentence Transformers

BGE

E5

MiniLM

MPNet

The quality of retrieval depends heavily on embedding quality.

---

STEP 5: VECTOR STORAGE

Embeddings are stored in a vector database.

Popular Vector Databases:

* ChromaDB
* Pinecone
* Qdrant
* Weaviate
* Milvus
* FAISS

These databases enable fast similarity search.

---

STEP 6: USER QUERY

User asks:

"What is transfer learning?"

The query enters the retrieval pipeline.

---

STEP 7: QUERY EMBEDDING

The question is converted into an embedding.

Example:

"What is transfer learning?"

↓

[0.45, -0.21, 0.88, ...]

Now both:

Documents

and

Query

exist in the same vector space.

---

STEP 8: RETRIEVAL

Similarity search finds the most relevant chunks.

Metrics:

* Cosine Similarity
* Euclidean Distance
* Dot Product

Top K retrieval is commonly used.

Example:

Top 5 most similar chunks.

---

TOP-K RETRIEVAL

K represents the number of retrieved chunks.

Examples:

K = 3

K = 5

K = 10

Tradeoff:

Small K

* Faster
* Less context

Large K

* More information
* More tokens
* Higher cost

---

STEP 9: CONTEXT AUGMENTATION

Retrieved chunks are inserted into the prompt.

Example:

Context:

Chunk 1

Chunk 2

Chunk 3

Question:

"What is transfer learning?"

The LLM now receives both:

Context

and

Question

---

STEP 10: GENERATION

The LLM generates an answer using retrieved context.

This is the Generation stage of RAG.

RAG VS FINE-TUNING

RAG

* External knowledge
* Easy updates
* Lower cost
* Real-time information

Fine-Tuning

* Changes model behavior
* Requires training
* Expensive
* Data updates require retraining

Interview Answer:

RAG is used to inject knowledge.

Fine-tuning is used to change behavior.

COMMON INTERVIEW QUESTIONS

Q: What is RAG?

A: Retrieval-Augmented Generation is a system that retrieves relevant information from an external knowledge source before generating an answer.

Q: Why is RAG needed?

A: To reduce hallucinations, access private data, and provide up-to-date information.

Q: What are the main components of a RAG system?

A: Documents, chunking, embeddings, vector database, retriever, and LLM.

Q: Why is chunking important?

A: It improves retrieval accuracy by allowing smaller, focused sections to be searched.

Q: What is Top-K retrieval?

A: Retrieving the K most relevant chunks from a vector database.

Q: Difference between RAG and fine-tuning?

A: RAG injects external knowledge, while fine-tuning changes model behavior.

Q: What is hybrid search?

A: Combining keyword-based and vector-based retrieval.

Q: What is re-ranking?

A: Reordering retrieved results to improve relevance.

Q: Which databases are commonly used in RAG?

A: Pinecone, ChromaDB, Qdrant, Weaviate, Milvus, and FAISS.

Q: How does RAG reduce hallucinations?

A: By grounding responses in retrieved evidence rather than relying solely on model memory.
