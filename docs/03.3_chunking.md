# Module 3.3 - Chunking Engineering

## Objective

Learn how to transform large documents into smaller semantic units suitable for embedding, storage, retrieval, and RAG systems.

Chunking is one of the most critical components of a Retrieval Augmented Generation (RAG) pipeline.

---

# What Problem Does Chunking Solve?

Large documents cannot be effectively retrieved as a single unit.

Example:

```text
100-page PDF
```

Embedding the entire document creates one giant vector.

When retrieval occurs:

```text
User Question
    ↓
Vector Search
    ↓
Entire Document Returned
```

This introduces noise and irrelevant context.

Chunking solves this by breaking documents into smaller meaningful segments.

---

# RAG Pipeline Position

```text
Document
    ↓
Chunking
    ↓
Embeddings
    ↓
Vector Database
    ↓
Retrieval
    ↓
LLM
```

Chunking is performed before embeddings are generated.

# Chunking in VIVA

VIVA uses:

```python
RecursiveCharacterTextSplitter
```

from LangChain.

Example:

```python
splitter = RecursiveCharacterTextSplitter(
    chunk_size=500,
    chunk_overlap=100
)
```

This creates overlapping text chunks that preserve context.

---

# RecursiveCharacterTextSplitter

LangChain's default text splitter.

Advantages:

* Simple
* Reliable
* Production-friendly
* Preserves document structure when possible

Common split hierarchy:

```text
Paragraphs
    ↓
Sentences
    ↓
Words
    ↓
Characters
```

The splitter attempts larger logical boundaries first before breaking text further.

# Chunk Size

Defines maximum chunk length.

Example:

```python
chunk_size = 500
```

---

## Small Chunks

Example:

```python
chunk_size = 100
```

Advantages:

* More precise retrieval
* Less irrelevant context

Disadvantages:

* Loss of surrounding information
* Reduced semantic completeness

---

## Large Chunks

Example:

```python
chunk_size = 1000
```

Advantages:

* More context preserved
* Better semantic completeness

Disadvantages:

* Noisier retrieval
* More irrelevant information

---

# Chunk Overlap

Overlap repeats content between neighboring chunks.

Example:

```python
chunk_overlap = 100
```

---

Without overlap:

```text
Chunk 1
Sentence A
Sentence B

Chunk 2
Sentence C
Sentence D
```

Important context may be split.

---

With overlap:

```text
Chunk 1
Sentence A
Sentence B

Chunk 2
Sentence B
Sentence C
Sentence D
```

Shared information helps preserve meaning across boundaries.

---

# Why Overlap Matters

Documents rarely contain independent sentences.

Meaning often spans multiple sentences.

Overlap reduces:

* Context fragmentation
* Retrieval errors
* Information loss

---

# Chunking Trade-Offs

| Small Chunks     | Large Chunks               |
| ---------------- | -------------------------- |
| Better Precision | Better Context             |
| Less Noise       | More Noise                 |
| Faster Retrieval | Slower Retrieval           |
| May Lose Meaning | May Return Irrelevant Data |

---

# Chunking Strategy Used In VIVA

Initial configuration:

```python
chunk_size = 500
chunk_overlap = 100
```

Chosen because:

* Good balance between context and precision
* Common production baseline
* Works well with interview knowledge documents

# Interview Questions

## What is Chunking?

Breaking large documents into smaller pieces before generating embeddings.

---

## Why Do We Need Chunking?

Large documents are difficult to retrieve effectively.

Smaller chunks improve retrieval quality and relevance.

---

## What Happens If Chunks Are Too Small?

* Loss of context
* Fragmented information
* Reduced retrieval quality

---

## What Happens If Chunks Are Too Large?

* More noise
* Irrelevant retrieval
* Reduced search precision

---

## What Is Chunk Overlap?

Repeated content between neighboring chunks used to preserve context.

---

## Why Use Overlap?

To prevent important information from being split across chunk boundaries.

---

## What Chunk Size Should Be Used?

There is no universal answer.

Depends on:

* Document type
* Embedding model
* Retrieval requirements
* LLM context window

Common starting point:

```python
chunk_size = 500
chunk_overlap = 100
```
